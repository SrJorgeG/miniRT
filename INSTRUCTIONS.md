## Introduction

There are two main approaches to rendering 3D computer-generated images:

- **Rasterization** — used by almost all graphics engines due to its efficiency.
- **Ray Tracing** — developed in 1968, more computationally expensive but produces a much higher degree of visual realism. Not yet fully adapted for real-time use cases.

**miniRT** is your first ray tracer coded in C — normed, humble, but functional. The main goal is to prove that you can implement mathematical and physical formulas without being a mathematician.

## Common Instructions

- The project must be written in **C**, following the **Norm**.
- Functions must not quit unexpectedly (no segfaults, bus errors, double frees, etc.). Any such crash results in a grade of **0**.
- All heap-allocated memory must be properly **freed**. Memory leaks are not tolerated.
- A **Makefile** is required, compiling with `-Wall -Wextra -Werror` using `cc`, and must not perform unnecessary relinking.
- The Makefile must contain at least the rules: `$(NAME)`, `all`, `clean`, `fclean`, `re`.
- To submit bonuses, include a `bonus` rule in the Makefile. Bonus files must use the `_bonus.{c/h}` suffix unless stated otherwise. Mandatory and bonus parts are evaluated separately.
- If `libft` is used, copy its sources and Makefile into a `libft/` folder. The project Makefile must compile it first.
- Test programs are encouraged but not submitted or graded — they are useful during defense.
- Submit to the assigned **Git repository**. Only work inside the repository will be graded.

### Allowed External Functions

- `open`, `close`, `read`, `write`, `printf`, `malloc`, `free`, `perror`, `strerror`, `exit`
- All functions from the **math library** (`-lm` flag required)
- All functions from the **MiniLibX library**
- `gettimeofday()`

### Requirements

- Use the **MiniLibX** library (system version or from sources).
- Window management must remain **fluid** (switching windows, minimizing, etc.).
- Implement at least these three geometric objects: **plane**, **sphere**, **cylinder**.
- All possible **intersections** and object **insides** must be handled correctly.
- Support resizing unique object properties: **diameter** (sphere), **width and height** (cylinder).
- Support **translation** and **rotation** transformations on objects, lights, and cameras (except spheres and lights, which cannot be rotated).
- Light management: **spot brightness**, **hard shadows**, **ambient lighting** (objects are never completely dark). Implement both **ambient** and **diffuse** lighting.
- The program displays the image in a window with the following behavior:
  - Pressing **ESC** closes the window and exits cleanly.
  - Clicking the **red cross** on the window frame closes the window and exits cleanly.
  - Use of **MiniLibX images** is strongly recommended.
- The program takes a `.rt` scene file as its first argument.
- If any misconfiguration is encountered in the scene file, the program must exit properly and return:
  ```
  Error
  <explicit error message>
  ```

### Scene File Format

- Elements can be separated by one or more **line breaks**.
- Element properties can be separated by one or more **spaces**.
- Elements can appear in **any order** in the file.
- Elements identified by a **capital letter** can only be declared **once** per scene.

## Bonus Part

> ⚠️ Bonuses are evaluated **only if the mandatory part is perfect** — complete and failure-proof. If the mandatory part does not obtain full points, bonuses are entirely ignored.

Bonus features to implement:

- **Specular reflection** — achieve a full Phong reflection model.
- **Color disruption** — checkerboard pattern.
- **Colored and multi-spot lights**.
- **One additional second-degree object** — cone, hyperboloid, or paraboloid.
- **Bump map textures**.

You are allowed to use additional functions and modify the scene file format to support bonuses. Be smart about it and justify your choices during evaluation.
